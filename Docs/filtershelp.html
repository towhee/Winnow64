How filters work

The filter panel has categories that contain items. For example the category Ratings can include the items 1, 2, 3, 4 and 5.

When you select multiple items in a category the filter is OR. In the ratings example, if 1 and 2 were selected then the filter is all images with a rating of 1 or 2.

Shift+click selects a range: every item between the last item you checked and the one you Shift+click is included. If they are all included already the same Shift+click clears them. Ranges work within one category only.

When you filter on multiple categories the filter is AND. If you also selected the Color Classes red and blue, then the filter will include all images with a rating of 1 or 2 and color class red or blue.

Excluding items

As well as choosing what to include, you can choose what to leave out. Opt+click (Alt+click on Windows) an item to exclude it — it is shown struck through in red. Right-click any item for Include, Exclude and Clear by name. Clicking an excluded item again clears it.

An exclusion always wins. If an image carries an excluded item it is left out whatever else it matches, and that applies across every category, not just within the one you excluded from.

A category holding only exclusions subtracts rather than narrows: excluding the color class red shows everything that is not red, not "nothing, because no image is in the empty set of included colors".

Keywords that mean two things

Keywords are flat. A keyword hierarchy such as Location > Canada > BC > Vancouver contributes each of its levels as its own keyword, so filtering on Canada finds everything that was beneath it — there is no tree to open.

The cost is that one name can mean two things. If you keyword both Location > Canada > BC > Vancouver and Location > USA > Washington > Vancouver, there is a single Vancouver keyword covering both cities. Winnow shows such a keyword in amber and lists its parents in the tooltip.

To tell them apart, include the keyword and exclude the parent you do not want: include Vancouver, Opt+click USA. The amber marking needs the catalog; without it Winnow cannot tell which keywords are ambiguous and marks none.

Writing a query

The Search category at the top of the Filter panel is a filter like the others, except that you type it. Click its row — the one reading Enter search query — type your query and press Return to run it. Nothing happens while you type: a query is run when you say it is finished, not on every keystroke.

Delete the text and press Return to remove the query; the row goes back to reading Enter search query. Unticking the row leaves the query in place but stops it filtering, and the No match row beside it does the opposite — it shows the images the query did not find.

Room to type, and queries worth keeping

Right-click the search row for three things the row itself cannot offer, above the usual filter commands:

  • Larger query space... — opens the query in a resizable window, with the operators listed beside it. Use it when a query has grown brackets and quoted phrases and no longer fits in the row.
  • Save query... — give the current query a name and keep it. Saving under a name you have already used replaces it.
  • Load query — picks a saved query and runs it. Hover a name to see the query it holds.

The two scopes

The same row searches whichever scope you are in — the dock title says which, Filters (Folders) or Filters (Catalog) — and the words mean the same thing in both:

  • Filters (Folders) — searches the images that are loaded now.
  • Filters (Catalog) — searches every image Winnow has catalogued, across all your folders.

F2 jumps to the search row of whichever scope you are in. To change scope, click the Catalog row above the Folders or Bookmarks tree, or use File > Open Catalog.

A search of the loaded folder that found nothing is one scope switch away from being asked of the whole library: the text carries across.

What is searched

Everything Winnow holds as text for an image: its full path — folder and filename — plus keywords, title, creator, copyright, colour label, camera make and model, lens, dimensions, the shooting information, and any e-mail or URL. A query does not search the picture itself — for that, use the AI masks in Develop.

The path being searched is easy to forget and occasionally surprising: a word that happens to be in your user name or a drive name is in every image's text.

Your own name is probably in most of your library. Creator and copyright are searched, and most cameras stamp them into every file, so searching for your own name will match nearly everything rather than narrowing anything. The same is true of a camera body you have owned for years. Add a second word.

The operators

Type this To find
heron nanaimo images with both words. Space means AND, which is the default.
heron AND nanaimo the same thing. AND is accepted because people type it.
heron OR eagle images with either word.
-heron images without the word.
NOT heron the same thing, spelled out.
"great blue" the phrase, not the two words in any order.
(heron OR eagle) tide brackets group — see below.

OR, AND and NOT are operators only in capitals. A photograph captioned "black or white" is searched for as written, because the lower-case or is just a word someone typed.

Brackets and what binds tightest

AND binds tighter than OR, which is the usual rule in search boxes and spreadsheets. So this:

heron OR eagle nanaimo

means heron, or (eagle and nanaimo) — every heron, plus the eagles at Nanaimo. Brackets say the other thing:

(heron OR eagle) nanaimo

which is anything at Nanaimo that is either a heron or an eagle. Brackets nest as deeply as you like:

((heron OR eagle) nanaimo) OR "great blue"

An unfinished bracket is not an error. A missing ) is closed for you at the end of what you have typed, and a stray one is ignored, so a half-written query narrows rather than failing.

To search for a bracket as a character — a filename like DSC(2) — put it in quotes: "DSC(2)".

Leaving things out

A -word or NOT word excludes it from the whole result, wherever in the query you write it. These all mean the same:

tide -heron
tide NOT heron
tide -(heron OR eagle)      excludes both

A NOT inside a bracket still applies to the whole query. heron OR -tide is read as heron, and not tide rather than as a choice, because that is the only reading the catalog index can carry out. If you mean two different exclusions, run them as two queries.

Examples

heron                         anything mentioning heron
"great blue" -captive         the phrase, minus one word
(heron OR eagle) 2024         either bird, in a folder or filename with 2024
Z9 (100-400mm OR 500mm)       one body, either of two lenses
nanaimo NOT (fog OR rain)     a place, in decent weather

Matching inside words

A word matches anywhere inside a word, in both scopes: eron finds Heron.

The exception is if you have set a limit on search results in Preferences. The catalog then holds only the newest images up to that limit, so the rest have to be found in the index instead — and the index matches from the start of a word, where eron finds nothing and her finds Heron.

The query and the ticks work together

The categories below Search do the other half of the filtering: tick a rating, a camera, a keyword or a colour label and the view narrows to it. A query and a tick are AND-ed like any two categories, and the tree is rebuilt for whichever scope you are in — a folder offers the three cameras in it, the library offers all forty.
